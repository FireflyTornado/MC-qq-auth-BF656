# 系统架构

## 组件与部署

```text
QQ 群 → NapCat → NoneBot2 → SQLite
NoneBot2 ── 提交后 POST 通知 ──→ FastAPI ←── 只读数据 ── SQLite
FastAPI ── HTTPS 快照 / WSS 更新提醒 ──→ Minecraft 插件
```

NapCat、NoneBot2 和 FastAPI 通常部署在同一台主机。NoneBot2 使用 OneBot v11 WebSocket 客户端连接 NapCat，接收目标群的消息和事件。Minecraft 运行在异地主机，插件通过受控的 HTTPS/WSS 入口接入授权 API。反代访问边界见 [部署说明](deployment.md)。

## 写入与授权版本

`/绑定` 和 `/解绑` 经过目标群过滤，将同步 SQLite 操作交给工作线程。`offline_bindings` 保存当前离线服绑定，每个群内的 QQ 只能有一条有效绑定，小写游戏名全库唯一。`/我的绑定` 读取有效记录，返回原始大小写。解绑删除对应的有效绑定。

绑定和撤销使用 `BEGIN IMMEDIATE`，在同一事务中写入授权记录并更新 `auth_state` 的 `id = 1` 单行。版本为整数，计算方式为 `MAX(旧版本 + 1, 当前 Unix 毫秒)`，同毫秒内写入或时钟回拨时仍可递增。版本行更新失败时，绑定变更也会回滚。SQLite 是授权状态的数据源，迁移由 `bot/migrate.py` 管理，已有绑定和版本会保留。

## 退群与成员对账

目标群的 `leave` 和 `kick` 事件使用与 `/解绑` 相同的撤销事务。没有有效绑定时，版本保持原值。近期重复事件在 Bot 进程内去重，事件时间早于绑定时间时保留新绑定。机器人自身离群会记录错误并暂停该账号的对账，收到其重新入群事件后解除暂停。成员重新入群后需要重新执行 `/绑定`。

Bot 在首次有效 OneBot 连接和重连后运行对账。名单无法确认时，连接仍有效才在 5 秒后重试一次。超级用户可在目标群用 `/授权对账` 手动触发，常态撤权由退群事件驱动。对账先记录当前授权版本和绑定行 ID，再比对两次 `get_group_member_list(no_cache=true)` 的结果和 NapCat `get_group_detail_info` 提供的成员数。两次名单必须一致、非空、包含机器人、没有重复成员，且行与群详情均属于目标群。查询期间收到成员变化事件或 OneBot 断开连接时跳过本次对账。通过名单校验后，数据库在写事务内再确认授权版本，防止删除对账期间重新建立的绑定。每批撤权推进一次版本并发出一次通知。

OneBot 的成员名单与群详情是独立请求。两次返回同一份旧名单，且人数仍与群详情相符时，结果可能通过校验。运行期间若遗漏成员事件且 OneBot 一直在线，需要人工对账或等下一次连接。成员在 Bot 离线期间退群又重新入群时，仅凭当前名单无法还原这段成员历史。两个相同且发生于同一秒的退群事件在 Bot 重启后缺少可持久区分的事件 ID。

## 提交、通知与快照

1. SQLite 提交成功后，Bot 才使用独立的 Notify Token 调用 `POST /internal/mc/notify`，并验证响应中的成功确认。网络故障不影响已提交的数据。
2. FastAPI 从 SQLite 读取最新版本。版本变化时向当前进程中已连接的客户端发送 `auth_updated`，消息包含版本号。API 还每 60 秒读取版本，补偿未成功送达的内部 POST。
3. `GET /internal/mc/snapshot` 在一个只读事务中读取版本号和目标群的有效小写名单，确保一次响应里的版本与名单来自同一数据库快照。

WebSocket 连接与广播去重状态保存在单个 API 进程内。广播串行推进版本，每个版本并发向客户端发送。发送失败时撤销连接登记，由该连接的处理器限时发送 `1011` 并结束处理，锁定版本的 Uvicorn 会结束底层连接。`delivered` 统计完成发送的连接数。客户端重连后读取 SQLite 的当前快照来补齐断线期间的变更。

## Minecraft 同步与准入

插件收到 WSS 的 `connected` 后通过 HTTPS 获取完整名单。收到更高版本的 `auth_updated` 后暂时暂停准入，合并提醒并串行刷新。快照达到已知最高版本后，插件将版本和不可变名单一次性发布给登录线程。已确认版本和更高版本提醒都会成为后续同步的下限，覆盖同一进程中的断线重连。

准入要求 WSS 已连接并且快照已同步。插件通过异步预登录检查游戏名，在同步登录和入服事件复查，以覆盖登录途中发生的撤销。应用新快照后，Bukkit 主线程检查在线玩家并移出失去授权的玩家。网络故障会暂停准入，在线踢出仅由已确认的快照触发。重连并完成全量同步后恢复准入。

现有 WSS 协议的发送结果只表明服务端已写出消息。极端情况下，若代理仍维持一条可响应心跳却无法交付授权通知的连接，现有客户端要等发现断线并重连后才能补齐。
